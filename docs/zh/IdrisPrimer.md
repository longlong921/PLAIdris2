# Idris2 Primer · 读懂记法

本扩展配合原有章节顺序，介绍全书使用的 Idris2 记法，不替代 [Naturals](Naturals.md) 或 [Equality](Equality.md)。

## 动机 {#motivation}

如果把证明助手的语法看成一套魔法指令，它就会显得神秘。本书中的证明，是返回类型十分精确的普通定义：构造子引入证据，模式匹配分析证据，递归调用提供归纳假设。认出这三种操作，大多数记法就有了着落。

我们从熟悉的函数开始，再改变返回类型所表达的内容。你只需要列表、二元组和递归的基本概念。

## 定义与类型 {#model}

{{include:src/PLFA/Extensions/IdrisPrimer.idr#definitions}}

`twice : Nat -> Nat` 是类型声明。后面的两条方程覆盖自然数的两种构造方式：`Z` 和 `S k`。后继分支递归处理 `k`，它是 `S k` 中更小的一部分。Idris 检查分支是否覆盖输入、递归是否递减。源码顶部的 `%default total` 使每个定义默认都必须满足这个要求；本书参考源码不会放宽它。

`Vect n a` 是元素类型为 `a` 的列表，其长度 `n` 被记录在类型中。`mapVector` 的类型说明映射保持这个索引，并没有说映射保持元素值：`f` 可以改变每个元素。空分支的长度为零；非空分支的结果具有与输入相同的后继长度。

签名中的 `n`、`a`、`b` 是隐式参数，调用时通常能从实参推断出来。推断需要帮助时，可以用花括号显式提供这种参数；用圆括号声明的参数则是普通显式参数。`public export` 让导入模块能使用定义及其实现；相等证明的检查过程有时需要展开该实现。

## 读一个小例子 {#examples}

计算 `twice 3` 时，要记住 `3` 简写了 `S (S (S Z))`。每一步从输入剥掉一个 `S`，并给输出添上两个。三次递归后，基础分支给出 `Z`，结果外面共有六个后继。这是按定义方程进行计算，并不是调用某个数值神谕。

在 `mapVector (\x => x) [2, 5]` 中，lambda 表达式 `\x => x` 是恒等函数。模式匹配取出第一个元素并保留它，然后递归处理只剩一个元素的尾部，结果为 `[2, 5]`。下面的证明把这个观察推广到*所有*向量，包括尚不知道长度和元素的向量。

## 把命题写成返回类型 {#theorems}

{{include:src/PLFA/Extensions/IdrisPrimer.idr#proofs}}

`twiceThree` 的结果是相等类型。两边都能计算成同一个表达式，所以 `Refl` 足够。对比 `mapIdentity`：未知向量不会因为写出了名字就展开，必须按构造子分情况。空分支可以直接计算；非空分支的递归证明说明两个尾部相等，`cong (x ::)` 把这个相等提升到“在两边加上同一个头部”的操作之下。

`swapTwice` 不需要归纳，因为二元组只有一个构造子，也没有递归尾部。取出两个字段后，两次交换都能计算。证明的形状取决于它分析的数据；不是所有数据类型上的定理都需要递归证明。

这些定理为显式量化的输入返回逐点相等证明。我们没有假设“只要两个函数对所有输入给出相等答案，它们作为 Idris 值就相等”。这个区别在 [Isomorphism](Isomorphism.md) 中很有用。

## 常见误区 {#pitfalls}

* 类型签名是目标，不是证明；实现必须属于该类型。
* 只在签名中出现的小写名字可能被隐式绑定。在类型中引用某个特定定义时，使用 `Module.name` 等限定名可以避免意外引入新参数。
* `Refl` 不是自动证明任意代数等式的工具，它依赖定义计算。符号化的右单位律经常需要归纳，而相应左单位律可能直接展开即可。
* `impossible` 用于类型检查器能够排除的构造子模式，不能用来打发难处理的分支。负向测试会检查错误命题不会悄悄通过。

## 习题与参考解答 {#exercises}

1. 证明对向量先映射 `g` 再映射 `f`，与一次映射两者的复合相同。命题应覆盖任意元素类型和任意向量长度。说明通过哪个构造操作提升归纳假设。参考：`mapCompose`。
2. 证明一个后继数的两倍等于其前驱两倍的两次后继。需要归纳吗？解释它为什么不同于关于函数没有检查的参数的定理。参考：`twiceSuccessor`。

第 1 题两边共同的头部为 `f (g x)`，尾部的相等来自递归调用。第 2 题的左边对任意 `n` 都能按定义方程展开，因此无需检查 `n`，直接用 `Refl` 即可。
