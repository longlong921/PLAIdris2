# Lambda：程序、绑定与归约 {#lambda}

## 动机 {#motivation}

定义一门程序语言，需要分清三个问题：什么算程序、执行一步做什么、哪些程序具有某个类型。
把它们分开，我们才能在下一章陈述一个有意义的定理：执行不会把良类型程序变成类型错误的程序。
如果类型只是附在求值器上的注释，就没有独立的命题需要证明。

本章的语言包含函数、自然数、分支和一般递归，可以表达加法、乘法以及永不终止的程序。
求值采用**从左到右的弱按值策略**：先求函数，再求实参，最后把实参代入函数体。
λ 的函数体即使含有可归约表达式，也不会因此自动在 λ 内部归约。

PLFA 在本章使用变量名，到后面才改用 de Bruijn 索引。本改编从一开始使用有作用域的索引，
但仍把类型判断放在语法之外。[DeBruijn](DeBruijn.html#model) 将比较“原始项加独立类型推导”
与“在表示中携带类型的项”。这个调整省去了变量名比较的细节，却没有排除类型错误的程序，
也没有省去类型保持证明。

## 模型 {#model}

### 类型、作用域与绑定 {#binding}

`Ty` 包含自然数类型 `TNat` 和函数类型 `Arr a b`。箭头在数学上向右结合：
柯里化加法的类型是 ℕ → (ℕ → ℕ)。`Context n` 是长度为 `n` 的类型向量，
表头对应最近引入的变量。

`Raw n` 可以提及当前作用域中的 `n` 个变量。`RVar` 的参数是 `Fin n`，因此无法构造越界索引。
`FZ` 指最近的绑定者；`FS FZ` 再向外一层。例如，λx. λy. x 的函数体使用索引一，
λx. λy. y 使用索引零。把纸面上的 x、y 改成其他名字不会改变这两棵语法树。

{{include:src/PLFA/Part2/Typed.idr#types}}

绑定只影响构造器指定的子项：

| 构造器 | 增加一个变量的子项 | 新变量表示什么 |
| --- | --- | --- |
| `RLam` | 函数体 | 函数实参 |
| `RCase` | 仅后继分支 | 被分析自然数的前驱 |
| `RFix` | 递归体 | 整个递归程序本身 |

`RCase` 的零分支不增加变量；后继分支绑定的是前驱，**不是**整个后继数。
`RFix` 绑定整个递归项；该项不一定是值，也不一定具有函数类型。

### 不发生捕获的替换 {#substitution}

重命名把变量映到变量；同时替换把变量映到项。两者都遍历所有构造器，但每进入一个绑定者，
都必须扩展映射。

{{include:src/PLFA/Part2/Typed.idr#maps}}

`liftRen` 保留新索引零，并将旧索引重命名后的结果向外移动一层。`liftSub` 同样保留新变量；
旧变量的替换项进入新绑定者下面之前，要经过 `rename FS` 弱化。这一步移动防止替换项中的自由变量
意外成为新绑定的变量。

例如，把函数体 λy. parameter 中的 parameter 替换成外层变量 `FZ`。在 λy 内部，
parameter 原来位于索引一。替换后，外层变量也必须处于索引一，结果才是 λy. outer。
如果错误地保留索引零，就会得到不同的程序 λy. y。
[DeBruijn](DeBruijn.html#exercises) 会检查这一具体计算。

`single` 把零替换成给定实参，并为其他变量移去一层绑定；`instantiate body arg` 就是由此得到的
单变量替换。它既适用于闭项，也适用于开放项，实参可以是任意项；求值规则会另外规定哪些位置要求实参为值。

### 类型是证据 {#typing}

`HasType gamma t a` 表示原始项 `t` 在上下文 `gamma` 中具有类型 `a` 的推导。
`TApp` 要求函数定义域与实参类型一致。`TCase` 要求被分析的项具有自然数类型，两个分支具有相同结果类型。
`TFix` 在额外假定递归变量具有最终结果类型的上下文中检查递归体。

{{include:src/PLFA/Part2/Typed.idr#typing}}

作用域保证的只是变量查找有意义。闭原始项“零应用于零”仍然能写出来，却没有类型推导。
同一个闭 λ 可以有多种外在类型：恒等函数既可具有 ℕ → ℕ，也可具有 (ℕ → ℕ) → (ℕ → ℕ)。
本章尚未实现类型推导算法。

### 小步执行 {#reduction}

值是 λ 或数值。特别地，只有 `t` 是值，`RSucc t` 才是值。
`Step t u` 记录一步归约，`Steps t u` 记录有限多步，包括零步。

{{include:src/PLFA/Part2/Lambda.idr#dynamics}}

`AppL` 求函数；只有函数已经是值，`AppR` 才开始求实参；`Beta` 只代入值。
`CaseStep` 求被分析的项，然后由 `CaseZero` 选择零分支，或由 `CaseSucc` 把前驱代入后继分支。
`Unfold` 将不动点本身代入其绑定变量，不要求它先成为值；若加上这个要求，递归就无法展开。

## 例子 {#examples}

`identityTwo` 是一步 β 归约。`plus` 的后继分支从近到远依次能看到：前驱、第二个实参、
第一个实参、递归函数。因此，带三个 `FS` 的变量表示递归函数，带一个 `FS` 的变量表示第二个实参。
先列出这个小上下文，比单纯数括号可靠。

{{include:src/PLFA/Part2/Lambda.idr#examples}}

附带的类型推导与程序具有相同树形，只是把语法构造器换成相应类型规则。
这是很合适的初次证明练习：加法的每次递归调用都要接收两个自然数，后继分支也必须返回自然数。

`churchTwo` 用重复应用表示二：给定 `s` 和 `z`，它计算 s (s z)。
其类型 `(a → a) → a → a` 与内建自然数类型不同。
编码本身是一个程序，并没有向语言增加新的构造器。

乘法在第一个实参上递归，将第二个实参加到递归结果上。
它的前驱分支采用与加法相同的四变量布局。

{{include:src/PLFA/Part2/Lambda.idr#multiplication}}

计算 `(λx. x) ((λy. y) 2)` 时，第一步用 `AppR` 得到 `(λx. x) 2`，第二步用 `Beta` 得到 `2`。
下方已检查的 `nestedIdentity` 正好记录这个顺序。
递归算术的运行结果在 [Properties](Properties.html#computations) 中检查。

## 本章证明了什么？ {#theorems}

`appendSteps` 证明两段有限归约可以连接。`applicationSteps` 把归约序列提升到应用的函数位置；
不需要假定实参为值，因为函数位置本来就先求值。
示例推导证明了恒等、加法、乘法、Church 二和常量函数的类型。

这些结果还没有证明所有闭良类型程序已经是值或能继续执行，也没有证明一步执行保持类型。
这些是 [Properties](Properties.html#theorems) 中单独的通用定理。
`Steps` 的定义也没有宣称每个程序都存在一条终止于值的有限归约序列。

## 常见误区 {#pitfalls}

- `Raw 0` 表示闭项，不表示良类型项。作用域正确与类型正确是两个不变量。
- λ 的函数体被调用后即使会发散，λ 本身仍是值。本章没有实现进入绑定者内部的完全 β 归约。
- 作用域大小中的 `S` 是宿主语言自然数构造器，`RSucc` 则是对象语言的项构造器，不应混淆两层语言。
- 穿过绑定者时必须用 `liftSub` 扩展替换；直接沿用原映射可能捕获变量。
- 下文写成 `Refl` 的证明只验证具体定义计算产生的等式。一般语义结论仍需要自己的证明。

## 习题与已检查解答 {#exercises}

1. **求值次序。** 写出恒等函数应用于“恒等函数应用于二”的完整归约。第一步由哪条规则支持？
2. **外层变量。** 编码 λx. λy. x，推导其类型 a → b → a，并说明为什么使用索引一。
3. **作用域与类型。** 证明“零应用于零”没有类型推导，尽管它是闭项。

{{include:src/PLFA/Part2/Lambda.idr#solutions}}

对应解答是 `nestedIdentity`、`constantType` 和 `zeroApplicationUntypable`。
第三题中，任何候选推导都必须包含“零具有函数类型”的推导，
但 `TZero` 只能产生 `TNat`，因此这个分支不可能。
