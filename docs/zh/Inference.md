# Inference：携带证据的双向类型检查 {#inference}

## 动机 {#motivation}

类型关系描述合法推导，却不会自动提供寻找推导的算法。
对于没有注释的 λ，检查器无法直接从语法读出实参类型；
对于应用，只要知道函数类型，就同时知道应该要求的实参类型与最后返回的结果类型。

双向类型化把这种不对称变成两个合作任务：从表达式**综合**一个类型，或者依据给定类型**检查**表达式。
本章把两者实现为总判定过程。成功时返回真正的推导；失败时返回一个函数，
证明任何候选推导都会导致矛盾。这比布尔值或 `Maybe Ty` 提供更多信息。

算法接收使用 `Fin` 变量的有作用域语法及长度匹配的上下文向量，不是文本解析器或命名变量解析器。
未绑定名字在进入本接口之前就被排除，因为没有越界的 `Fin` 值。
作用域正确的输入仍可能有类型错误，这些错误在这里被真正判定。

## 模型 {#model}

### 两种模式与两种切换 {#syntax}

语法互递归定义。`SynthTerm` 包含变量、应用和类型注释；
`CheckTerm` 包含 λ、零、后继、自然数分支、不动点，以及综合项的嵌入。

{{include:src/PLFA/Part2/Inference.idr#syntax}}

| 形式 | 模式 | 信息流 |
| --- | --- | --- |
| 变量 | 综合 | 从上下文读取类型 |
| 应用 | 综合 | 综合函数类型，按其定义域检查实参 |
| 有注释项 | 综合 | 按注释检查，再返回该类型 |
| λ | 检查 | 将期望箭头拆成定义域与值域 |
| 零、后继 | 检查 | 要求 `TNat` |
| 分支 | 检查 | 综合自然数被分析项，按期望结果检查两个分支 |
| 不动点 | 检查 | 赋予递归变量期望结果类型 |
| 嵌入的综合项 | 检查 | 先综合，再与期望类型比较 |

`Annotate` 从检查语法切换到综合语法，`Embed` 切换回来。
如果 λ 已经在一个箭头期望类型下接受检查，就不必另写注释。
顶层 λ 若必须综合类型，可在整个项外提供一个注释。

### 判断 {#judgements}

`Synth gamma t a` 和 `Check gamma t a` 是对应两种模式的独立证据类型。
在 `ChEmbed` 中，显式相等证明连接综合类型与期望类型。
应用规则不任意搜索实参类型，因为函数前提已经给出定义域。

{{include:src/PLFA/Part2/Inference.idr#judgements}}

`SyApp` 的定义域参数与 `ChEmbed` 的综合类型参数作为可计算的隐式参数保留。
这对 Idris 很重要：构造失败证明时，可能要重建一个包含该类型的存在包。
上下文和语法索引仍然擦除。保留这些证据是实现选择，不是新增类型前提。

## 例子 {#examples}

`identityTwo` 把恒等函数注释为 ℕ → ℕ，再应用于二。
注释要求 λ 在 `TNat` 下检查主体；变量综合出 `TNat`，`Embed` 验证它与期望类型相同。
实参二通过结构检查，无须再加注释。

{{include:src/PLFA/Part2/Inference.idr#examples}}

递归加法只在最外层提供 ℕ → ℕ → ℕ 注释。
`CFix` 将这个类型放入上下文，两个 λ 各自获得定义域，分支再按期望自然数结果检查两边。
后继分支中的上下文从近到远是前驱、第二实参、第一实参、递归函数。
因此，只增加模式切换，就能重建前面的算术程序，不必给每个变量或子表达式标类型。

`plusAccepted` 检查加法应用于二和二时综合成功。
手写的 `identityTwoDerivation` 则是便于阅读的判断实例；一般算法不依赖这份特定证明。

## 算法正确性 {#theorems}

### 类型相等与综合唯一性 {#uniqueness}

`typeEqual` 递归判定简单类型的相等。不同外部构造器不可能相等。
对于函数类型，分别比较定义域和值域；任一分量不等，整体相等就会推出该分量不可能的相等。

`synthUnique` 表示：**同一上下文中的同一个有作用域项**，若有两份综合推导，结果类型必相等。
应用分支对函数使用归纳假设，再提取值域相等；注释则直接固定结果类型。
这没有断言擦除后的原始语言类型唯一：恒等函数可以在多种箭头类型下通过检查。

{{include:src/PLFA/Part2/Inference.idr#equality}}

### 真正提供失败证据的判定 {#decision}

`synthesize` 返回 `Dec (a : Ty ** Synth gamma t a)`，
`check` 返回 `Dec (Check gamma t a)`。
两个函数在子表达式上互递归，包括在扩展上下文中检查绑定体。

{{include:src/PLFA/Part2/Inference.idr#decision}}

应用的失败分支解释了唯一性为何必要：

1. 若函数综合失败，任何成功应用推导都必须包含函数推导，与失败证据矛盾。
2. 若函数综合出 `TNat`，成功应用却要求它具有函数类型，`synthUnique` 与 `natNotArrow` 排除这种可能。
3. 若函数综合出箭头，但实参检查失败，另一份应用推导可能写着一个表面不同的定义域。
   唯一性证明两个定义域相等，`convertCheck` 再把其参数推导搬到被拒绝的类型上，形成矛盾。

嵌入分支采用相同模式：不能通过换一份综合推导绕开失败的相等比较，因为综合类型唯一。
这些分支提供的是失败证明，不是没有解释的 `Nothing`。

### 可靠性、内在化与擦除 {#soundness}

互递归擦除函数移去类型注释和模式切换，留下 [Lambda](Lambda.html) 的原始语法。
`synthSound` 和 `checkSound` 把每份双向推导转换成擦除项的外在 `HasType` 推导。
构造器分支重建相应类型规则；嵌入分支通过匹配 `Refl` 消去类型相等。

{{include:src/PLFA/Part2/Inference.idr#soundness}}

`elaborateSynth` 和 `elaborateCheck` 随后复用
[DeBruijn](DeBruijn.html#correspondence) 的一般对应，产生内在项。
`synthErasure` 与 `checkErasure` 证明：忘记这些项的类型索引，得到的原始语法与直接擦除注释一致。
因此，检查成功提供的是一个可执行、带类型且与输入具有已证明联系的程序。

### 这里的完备性是什么意思？ {#completeness}

`No` 结果本来就反驳所查询判断的任何推导。
`synthesizeComplete` 与 `checkComplete` 显式给出其后果：只要存在综合或检查推导，
对应过程的成功标记就是 `True`。失败分支把反驳函数应用到给定推导，得到矛盾。

{{include:src/PLFA/Part2/Inference.idr#completeness}}

完备性相对于**这些双向判断以及输入中的这些注释**。
它不是说“只要原始程序能赋类型，对它随便加什么注释都会被接受”。
尤其是把零注释为函数类型必须失败，尽管擦除后的零具有 `TNat` 类型。
第三道习题同时检查这两件事。

### 从输入到计算结果 {#execution}

`inferredTerm` 对加法示例运行综合，保留自然数类型的内在结果。
`inferredTermCorrect` 将它与前面的内在加法程序对应起来。
`inferredComputed` 把这个等式经带燃料求值器搬运，检查结果为 `Just 4`。

{{include:src/PLFA/Part2/Inference.idr#execution}}

两阶段证明显式呈现了编译和执行之间的联系。
它复用已经证明的可靠性与内在求值器，没有为带注释语法另外引入未经验证的解释器。

## 常见误区 {#pitfalls}

- 检查与综合是两个接口。无注释 λ 属于检查语法，不是实现漏掉的综合分支。
- 成功检查返回推导，失败检查必须反驳推导；只返回布尔值会丢失两种保证。
- 综合唯一性针对包含注释的双向项，不是无注释原始项的主类型定理。
- 有作用域变量把名字解析错误排除在输入数据类型之外，没有消除“应用零”等类型错误。
- 类型相等比较简单类型的语法；本语言没有子类型或隐式强制转换。
- 类型正确不意味着求值终止；`CFix` 同前几章一样保留一般递归。

## 习题与已检查解答 {#exercises}

1. **检查恒等函数。** 对任意类型 `a` 和任意上下文，证明检查式恒等函数具有 a → a 类型，解释这为何不违背综合唯一性。
2. **拒绝所有结果类型。** 证明“注释为自然数的零应用于零”不能综合任何类型，并检查算法的失败标记。
3. **注释有意义。** 把零注释为函数类型，检查综合拒绝它，同时证明擦除后的原始项仍具有自然数类型。
   陈述经此反例仍然成立的完备性命题。

{{include:src/PLFA/Part2/Inference.idr#solutions}}

对应解答是 `identityAt`；`badApplicationImpossible` 与 `badRejected`；
以及 `annotationRejected` 与 `erasureStillTyped`。
最后一对构成有用的边界检查：可靠的检查器必须尊重注释，不能悄悄换成一个方便通过的类型。
