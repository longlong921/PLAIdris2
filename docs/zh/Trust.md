# Trust · 对象语言与宿主语言

## 动机 {#motivation}

“这个证明通过了 Idris”是有用的信息，却还不完整。检查的是哪个命题？哪些定义赋予这个命题含义？负责检查的是哪个实现？严谨的说明要区分三层：数据所描述的对象语言、关于这些数据陈述的数学元理论，以及检查实现的 Idris 编译器。

回到完整 lambda 演算前，我们先用一台极小的机器分清这三层。这个扩展机器只是补充主线，不替代任何关于 lambda 项的定理。

## 一个可以一直运行的语言 {#model}

{{include:src/PLFA/Extensions/Trust.idr#machine}}

`Halt` 没有迁移，`Spin` 可以迁移回自己。`Trace n before after` 记录恰好 `n` 步，其构造子描述的是*有限证据*。对每个自然数 `fuel`，`spinFor fuel` 都能构造一条恰好走这么多步、从 `Spin` 回到 `Spin` 的轨迹。

`spinFor` 是总函数，因为宿主递归中的 `fuel` 递减。被描述的机器却不会终止：无论观察了多少有限步骤，下一步 `Again` 总是可用。两句话并不矛盾：一句说的是构造有界描述，另一句说的是无限制地执行所描述的系统。

## 燃料是预算，不是发散证明 {#examples}

{{include:src/PLFA/Extensions/Trust.idr#observations}}

`runFor 4 Spin` 消耗四单位燃料后返回 `OutOfFuel`。`runFor 0 Halt` 返回 `Finished`，因为机器已经结束。对这台特定机器，我们可以证明对*每个*燃料值都成立的 `spinExhausts`。但任意 lambda 项的一次超时并不能证明发散：更大的预算可能得到结果。

在 [Untyped](Untyped.md) 中，`Ω` 是一个能一步回到自己的具体 lambda 项。[BigStep](BigStep.md) 另外证明它没有有限的按名调用求值推导。证明相应不收敛性质的是这个论证，而不是任意选择的超时。[Confluence](Confluence.md) 研究有限完整 β 归约路径的汇合，与这个例子完全兼容。

## 检查究竟说明什么 {#theorems}

源码中的 `spinExhausts` 对预算做结构归纳，`haltFinishes` 直接来自定义方程。两个定理都没有说证明检查器本身正确。本书的信任链包含精化（将表层程序补全为核心项）、类型转换、覆盖与终止检查、导入库，以及编译器实现。运行编译后的例子，还依赖代码生成与所选运行时。

Idris2 0.8.0 自身的[版本化 FAQ](https://github.com/idris-lang/Idris2/blob/v0.8.0/docs/source/faq/faq.rst)将其宇宙实现描述为 `Type : Type`。因此，被这个编译器接受，并不等同于在具有可靠直谓宇宙层级的基础逻辑中完成形式化。禁用显式逃逸并要求总性，不能修复这一全局基础限制。我们不声称证明宿主的一致性，也不利用这个宇宙限制制造证明。

本书提供的是遵守约束、可以检查的构造性证明程序，由确定版本的编译器验证。读者还能独立审视定义与结构论证。沿用上游定理的名字并不会自动转移它的正确性；翻译后的命题及实现都需要审查。

自动套件检查未完成洞和被禁止的信任逃逸、编译所有参考模块、运行例子，并要求拒绝刻意写错的证明。它也验证目录结构、引用源码哈希与本地链接。这些测试能够发现具体类别的错误，但并不证明测试器完备，更不证明编译器的元理论。

## 常见误区 {#pitfalls}

* 进展性与保持性建立一种安全性；有一般递归时，它们不建立终止性。
* 大步关系描述成功的有限求值。“没能构造出推导”本身不是发散证明；反证必须排除每种可能的有限推导。
* 合流性不等于单步确定性，两者也都不能独自保证正规化。
* 宿主表示类型正确，不会使一个写错的对象语言规则自动变得数学上合适。定义必须与定理一同审查。
* 错误证明只有因预期原因被拒绝，才提供有用的负向测试证据；找不到编译器或导入模块不算成功。

## 习题与参考解答 {#exercises}

1. 证明 `Halt` 没有向外的迁移。假设存在迁移，它只能使用哪个构造子？其源索引为何使这种情况不可能？参考：`noHaltStep`。
2. 证明每条从 `Spin` 开始的有限轨迹也在 `Spin` 结束。解释为什么证明此结果不需要执行无限计算。参考：`traceStaysSpin`。
