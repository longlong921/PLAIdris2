# More：一致地扩展类型化语言 {#more}

## 动机 {#motivation}

增加语法构造器只是扩展语言的开始。类型规则、绑定结构、值的定义、求值次序、替换行为与进展分支
都必须彼此一致。例如，积构造器如果没有求第二个分量的规则，就可能让闭良类型程序卡住。

本章给内在类型化演算增加原始数字与乘法、`let`、积、和、单位、空类型和列表。
上游可执行核心集中在原始数字、let 与积，正文和习题介绍了其余构造。
本章在同一个语言中为这些构造全部实现重命名、替换、按值归约与闭项进展。

## 模型 {#model}

### 引入、消去与绑定 {#constructs}

`NatT` 是具有零、后继和分支的一元自然数类型。`PrimT` 是另一种原始数字类型，
其字面量保存宿主 `Nat`，`Times` 直接计算乘法。
将两者分开，能看清归纳编码与原始操作的区别。

{{include:src/PLFA/Part2/More.idr#syntax}}

可以按引入与消去的对应关系阅读新增构造：

| 类型或构造 | 引入 | 消去 | 新增绑定者 |
| --- | --- | --- | --- |
| 函数 | `MLam` | `MApp` | λ 体中一个 |
| `let` | 绑定表达式与主体 | 表达式成为值后替换 | 主体中一个 |
| 积 | `Pair` | `Fst`、`Snd`、`Split` | `Split` 主体中两个 |
| 和 | `InL`、`InR` | `SumCase` | 每个分支各一个 |
| 单位 | `Unit` | `UnitCase` | 无 |
| 空类型 | 无 | `Absurd` | 无 |
| 列表 | `Nil`、`Cons` | `ListCase` | cons 分支中的表头与表尾 |

和类型的注入确定所选分量，另一个分量的类型则来自内在期望类型。
`SumCase` 的两个分支必须返回相同类型。列表只有一个元素类型，表尾也必须具有相同列表类型。
只要参数具有 `EmptyT` 类型，`Absurd` 就可以具有任意结果类型，不需要提供值证明。
执行时先求该参数；空类型没有值，因此也不存在取得空类型值之后的消去规则。

### 一个绑定者与两个绑定者 {#substitution}

所有构造器都要参与结构操作。新增的关键分支是 `Split` 与 `ListCase` 的 cons 分支：
它们的映射需要扩展两次。普通积的两个分量不绑定变量。

{{include:src/PLFA/Part2/More.idr#structural}}

上下文顺序必须明确。拆开类型为 a 与 b 的积，主体上下文是 b :: a :: Γ：
零选择第二分量，一选择第一分量。列表 cons 分支的顺序是 ListT a :: a :: Γ：
零选择表尾，一选择表头。`double first second` 显式实现这个约定，`inst2` 同时完成两处替换。

这里没有把两个单替换不加解释地复合起来。移除一个绑定者会改变剩余索引，替换项本身也可能是开放项。
同时映射在遍历之前就说明每个变量的预期含义；进入更多绑定者时，弱化由通用机制处理。
下方的已检查习题会区分这两个位置。

### 值与求值次序 {#dynamics}

λ、一元数值、原始字面量和单位都是值。积、注入和 cons 单元只有在内部项均为值时才是值。
因此列表会求值表头和表尾，并不是惰性流。`EmptyT` 没有值构造器。

{{include:src/PLFA/Part2/More.idr#dynamics}}

每个严格二元构造都从左到右求值。投影会等到积的**两个**分量都是值，即使它最终丢弃其中一个。
`SumCase` 先求被分析项，包括已选注入携带的内容，再只向选中的分支替换。
`ListCase` 先得到完全求值的列表值，再向 cons 分支同时代入表头与表尾。
分支主体不会在选择之前被求值。

投影与积模式匹配以不同形式表达字段选择。第一投影可用 `Split` 加选择索引一的主体表示，
第二投影则选择索引零。反过来，可以先用 let 保存积，再分别用投影取得字段；
先保存能保留被分析项只求值一次的意图。这些是解释性的翻译，本章不声称已经证明两种积形式之间的一般等价定理。
已检查的 `swapPair` 和 `splitOrder` 直接演示双绑定者形式。

`Let` 在替换前先将绑定表达式求值一次；绑定表达式还在执行时，不归约主体。
下一章会证明，把 let 改写为 λ 应用遵守这些精确规则。

## 扩展语言的定理 {#theorems}

### 闭项进展 {#progress}

`progress` 处理每个构造器。辅助函数表达相应规范形式：原始数字值必须是字面量，
积值必须是积，和值必须带标签，列表值必须是 nil 或由值组成的 cons。
对于 `Absurd`，若参数能执行，就产生上下文步骤；若参数是值，则由 `emptyValue` 排除。

{{include:src/PLFA/Part2/More.idr#progress}}

所有归约在构造时保留类型和上下文索引；构造 `SplitBeta` 与 `ListCons` 依赖正确的带类型 `inst2`。
闭合性仍不可缺少，因为开放变量在这些规则中既不是值，也不是可归约式。

### 值不能执行一步 {#normality}

`valueNormal` 覆盖扩展后的全部值语法。对于积或 cons，上下文步骤要求某个已经是值的分量继续执行，
因此对该分量的值证据递归即可。注入和后继分支具有同样结构。
字面量、单位、nil 和 λ 则没有任何适用的归约规则。

{{include:src/PLFA/Part2/More.idr#value-normal}}

空类型没有**值**，但一般递归允许该类型存在闭项。下列项展开到自身，并不与 `emptyValue` 矛盾，
因为它永远不成为值。若混淆“没有值”与“没有项”，就会错误地把带一般递归的程序语言当成可正规化逻辑。

{{include:src/PLFA/Part2/More.idr#empty-loop}}

### 产生证据的求值 {#evaluation}

带燃料求值器用进展构造归约轨迹。`Returned` 包含值证明，`OutOfFuel` 不作终止结论。
即使被表示的程序（例如 `emptyLoop`）永远运行，按燃料递归的求值器本身仍是总函数。

{{include:src/PLFA/Part2/More.idr#evaluation}}

## 常见误区 {#pitfalls}

- 原始乘法接收 `PrimT`，不是一元 `NatT`。它们是两种不同的对象语言类型。
- 含有未求值表达式的积不是值；投影不能悄悄跳过被丢弃分量的求值。
- `Split` 与列表 cons 分支都绑定两个变量，顺序已经明确，映射也必须扩展两次。
- 和类型分支只执行选中的主体，但先要求被携带的内容成为值；这是按值求值。
- `EmptyT` 没有值。一般递归阻止我们推出“它没有闭项”这一更强结论。
- 只向 `Term` 增加构造器而不扩展全部结构和执行函数，会留下不完整的语言定义；总性检查有助于发现漏掉的分支。

## 习题与已检查解答 {#exercises}

1. **积的绑定顺序。** 拆开字面量三和五构成的积，将第一分量乘以第二分量，证明乘法执行之前的精确替换结果。
2. **和类型选择。** 分析携带七的左注入，将其内容乘二，右分支给定一个常量，证明一步选择的目标。
3. **列表绑定。** 分析只含九的单元素列表并返回表头，解释为什么分支使用两个新变量中较旧的那个。
